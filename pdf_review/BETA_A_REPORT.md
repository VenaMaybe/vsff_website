# Private Beta A implementation report

Completed locally on November 1, 2026. No deployment or VSFF changes were performed.

Follow-up local configuration: at the user's explicit request, the Google client credentials from their downloaded client JSON were saved in ignored `.env`, with a generated persistent session secret and the registered loopback callback. `app.py` and Flask CLI now load this file with python-dotenv (`>=1.0,<2`; installed 1.2.4), respecting existing process environment variables. No credentials were copied into this report, tracked source, or `.env.example`. Google account sign-in and allowlist/ACL bootstrap still need manual completion.

1. **Implementation.** Added Google authentication, verified-email allowlisting, explicit document ACLs, safe legacy linking, mutation CSRF, secure session configuration, HTTP headers, socket authorization, and offline administration. Removed freely selectable reviewer identities from normal UI/APIs. Existing review, anchor, version, target and migration services remain intact. Comment deletion now enforces original authorship, matching the requested own-comment permission model.

2. **Dependencies.** `requirements.txt` now requires Flask `>=3.1.3,<4` (including supported trusted-host validation), Flask-SocketIO `>=5.7,<6`, Authlib `>=1.9.1,<2`, and requests `>=2.32.5,<3`. Installed and tested in the project `.venv` with Flask 3.1.3, Flask-SocketIO 5.7.0, Authlib 1.9.1 and requests 2.34.2. `pip check` reports no broken requirements. Authlib's documented [Flask OIDC integration](https://docs.authlib.org/en/latest/oauth2/client/web/flask.html) handles the protocol; no custom JWT validation was introduced.

3. **Migration/schema.** Added numbered migration 6 (`google_identity_and_document_access`) without modifying migrations 1–5. User additions: unique nullable `google_subject`, email, unique nullable normalized email, boolean verified-email flag and last-login time. Added `allowed_emails` (unique normalized email, enabled flag, creation time, nullable creator/note) and `document_access` (document/user composite key, constrained role, creation time, nullable grantor). Foreign keys, role/boolean/subject checks and indexes enforce integrity; a trigger forbids changing an established subject. No existing document or user received an automatic allowlist entry or grant.

4. **Google OIDC.** Routes are `/auth/login`, `/auth/google`, `/auth/google/callback`, `/auth/denied`, and POST `/auth/logout`. Google discovery is `https://accounts.google.com/.well-known/openid-configuration`; scopes are exactly `openid email profile`. Authlib performs server-side authorization-code exchange with state, nonce, signature/issuer/audience/expiry validation and PKCE S256. Callback consumes only validated ID-token claims. No ongoing Google API or offline access is requested. Tokens remain transient in request memory and are never stored in the cookie, database or rendered pages. Return URLs are restricted to local absolute paths.

5. **Allowlist.** Only active local users with a linked subject, verified email and an enabled matching database allowlist entry may use protected sessions. Google Cloud's test-user list is not application authorization. Email normalization strips surrounding whitespace and case-folds, preserving dots, plus tags and domains. Disabling/deleting an allowlist entry blocks the next protected HTTP request and future socket connections/joins.

6. **Stable identity/linking.** A matching subject resolves the same user ID, updating safe current profile fields only after the new verified email passes the allowlist. A first subject can link to exactly one explicitly email-prepared active legacy user. Display-name coincidence never links accounts; conflicting subjects/emails and ambiguous rows fail closed. A new allowed account without legacy preparation gets a new stable user, with no access to old documents. All historical author/editor/resolver/migration foreign keys remain unchanged.

7. **Document ACL.** Owner: document/PDF/discussion/history reads, review mutations, own-comment edits/deletion, imports/integrity actions and migration mutations. Reviewer: reads, comments/replies, own-comment edits/deletion and resolve/reopen. Viewer: reads only. All may read authorized migration history. Globally allowed accounts may create new logical documents; the creator becomes owner in the same transaction. CLI administration is independent of document roles. No account, including an owner, may edit/delete someone else's comment.

8. **HTTP protection.** `review/auth.py` has an explicit protected-endpoint registry and default-deny before-request policy. Tests check that every core/carry route is registered. Each resource ID resolves to its logical document before content handlers execute. Anonymous page requests redirect to login, anonymous API/mutation requests receive 401, inaccessible/missing resources receive generic 404, and insufficient roles on accessible resources receive 403. The dashboard filters documents; `/api/reviewers` exposes only the current account. POST reviewer creation is no longer supported (405 on the read-only collection); the identity-switch route is gone (404).

9. **PDF bytes and Range.** Authentication and ACL checks precede version content lookup, blob resolution, verification and `send_file`. GET, HEAD, valid/malformed/unsatisfiable Range and conditional requests share this gate. Authorized reads retain ordinary PDF and 206 responses. Unauthorized tests assert the blob resolver is never called, no PDF bytes/path are returned and no Content-Range is exposed. Blobs remain outside static; no public/signed/download-token URL was added. Flask denies the unused vendored sample PDF without modifying PDF.js files.

10. **Socket.IO.** Connect requires current authenticated/active/allowlisted identity; joining `version:<id>` additionally checks that version's document grant. Presence uses database identity and ignores supplied IDs/names. Viewers may receive updates but cannot mutate HTTP review content. Exact-version isolation, reconnect refetch and post-commit broadcasts remain intact. Explicit origin validation avoids Engine.IO's implicit forwarded-host/protocol trust, using configured public origin or direct WSGI origin in unconfigured loopback development. Forwarded-header origin spoofing is tested and rejected.

11. **CSRF.** A random token lives in the signed application session. Templates expose it to app-owned code via a meta element; HTML mutation forms use hidden fields. `static/review/http.js` centrally attaches `X-CSRF-Token` for POST/PATCH/PUT/DELETE across anchor/discussion/migration clients. The server compares token bytes in constant time. Logout is POST and requires CSRF. Safe GET/HEAD do not. OAuth state remains separate.

12. **Sessions/cookies/proxy/headers.** The authenticated cookie contains stable `authenticated_user_id`, CSRF state and lifetime metadata, with a 12-hour rolling lifetime. HttpOnly and SameSite=Lax are enforced; production requires Secure and HTTPS. Production refuses missing credentials/host or secrets shorter than 32 characters before database initialization. Development supports HTTP and logs an ephemeral-key warning if no persistent secret is supplied; it never bypasses authentication. Host validation and configured scheme/host protect callback generation. Proxy trust defaults to zero; optional one-hop ProxyFix trusts only scheme and requires a sole isolated ingress. Flask responses use nosniff, same-origin referrers and SAMEORIGIN framing; protected/auth responses are private/no-store. Production adds one-year HSTS. Existing PDF.js CSP is preserved.

13. **Administrative CLI.** Use `python -m flask --app app` followed by:

    | Command | Purpose |
    | --- | --- |
    | `list-identities` | List stable user and document IDs for bootstrap |
    | `allow-email EMAIL [--note TEXT]` | Add/re-enable an email |
    | `disallow-email EMAIL` | Disable an email |
    | `list-allowed-emails` | List allowlist state |
    | `link-google-email EMAIL USER_UUID` | Prepare a legacy user before first Google login |
    | `grant-access DOCUMENT_UUID USER_UUID --role owner\|reviewer\|viewer` | Add/change a document grant; choose one role |
    | `revoke-access DOCUMENT_UUID USER_UUID` | Remove a document grant |
    | `list-document-access DOCUMENT_UUID` | List grants |
    | `verify-storage` | Existing immutable PDF verification |

20. **Known limitations.** Existing idle joined sockets are not forcibly disconnected immediately after revocation/logout; they may receive room notifications/presence until disconnect. The next HTTP request, connect/join, and page report check current authorization. Local cookie logout does not remotely invalidate a copied signed cookie or a different browser's session; use allowlist/user disablement or document revocation for account-wide blocking. Authorized users can retain already downloaded PDFs. Development keys are ephemeral unless configured. Sessions remain signed client cookies, not a server-side session registry. The app retains its single-process realtime architecture. Real Google sign-in/consent, HTTPS and a deployed reverse proxy still require manual acceptance. No deployment/admin web UI or automatic migration was added.

21. **Decisions/deviations.** Implemented all three roles rather than the minimum two. Restricted migration mutations/import/integrity actions to owners and documented that policy. Strengthened deletion to original authors as required for the beta permission model. Added PKCE, explicit socket origin checks and Flask trusted-host support as supporting safeguards. Static code/assets remain public for login/viewer bootstrapping, while all private content and all PDF byte routes are protected. Tests now establish explicit authenticated fixtures instead of selectable-reviewer requests; no test bypass exists in production routes. Real Google and deployment acceptance could not be executed without account credentials/infrastructure; complete manual instructions are supplied. No unrelated repository was changed.
